# Передача работы: начни здесь (для любой нейросети — Claude, GPT/Codex, Gemini, Cursor, Copilot…)

Этот файл — короткий вход. Подробные правила — [`AGENTS.md`](../AGENTS.md) (прочитай его целиком первым).

## 1. Что это

Мод **SA Coop** — кооператив для GTA San Andreas Android 2.10 arm64 (AML-мод `libSACoop.so`, C++17, NDK r27c).
Игрок (не программист, говорит по-русски) и его друг играют вдвоём через интернет: Турция ↔ Бельгия.
Рядом — второй мод **SA Living** (ИИ-педы и Джарвис, папка `sa-living/`, выпущена 0.2.0).

* Репозиторий: `STREDGE/linux`, рабочая ветка **`ccr-ffecc13b-oyswo0`** (в `main` не писать, PR не делать без просьбы).
* Репозиторий **публичный** → никаких файлов игры, ключей API, сохранений и голоса игрока.

## 4. Главные решения игрока (кратко; полностью — в ТЗ)

* «Кооп — как соло-игра, только с другом»; **ничего не должно быть видно глазом** (никаких подмен, скачков, рывков).
* Только оригинальные кнопки игры, без своих «костылей».
* Без коопа мод ничего не меняет (одиночная игра и её сохранения нетронуты).
* Связь — **встроенный Tailscale** (своего сервера не будет). ID точки — 6 цифр.
* Хост — хозяин мира; в 1.1 — «кто ближе — тот хозяин» для педов и машин.
* Кооп-сохранения — свой зашифрованный формат `.sacoop`, привязан к паре, в соло не грузится, кооп-мир только в коопе.
* ИИ (SA Living) в коопе **всегда платит хост**; ключ API никогда не вшивается и не передаётся.
* Подробные логи «каждой пылинки» — обязательны.

## 5. Сборка за 3 команды

```sh
# нужны: Android NDK r27c, Go (сам скачает нужную версию), python3; хосты: dl.google.com, proxy.golang.org
NDK=/opt/android-ndk-r27c bash tools/tsbridge/build.sh          # встроенный Tailscale (один раз)
$NDK/ndk-build NDK_PROJECT_PATH=. APP_BUILD_SCRIPT=jni/Android.mk NDK_APPLICATION_MK=jni/Application.mk -j8
cp libs/arm64-v8a/libSACoop.so release/
```

Нет NDK/Go у тебя — GitHub Actions (`.github/workflows/build.yml`) собирает на каждый push → Artifacts.

## 6. Как общаться с игроком

* По-русски, коротко, без терминов. Ему нужен готовый `.so` файлом и «что нажать».
* Перед большой работой — согласовать (он любит, когда сначала ТЗ). Решения записывать в ТЗ/AGENTS сразу.
* Честно говорить, что проверено, а что нет. Сроки: «написать код» ≠ «работает в игре» (проверяет только он).
* Если у тебя нет доступа к репозиторию — попроси у игрока ссылку на ветку или файлы `AGENTS.md`,
  `docs/HANDOFF.md`, `docs/TZ-1.1.md`, `docs/ARCHITECTURE.md`.
