# Памятка для ИИ-помощника (Claude, GPT/Codex, Cursor и др.) — SA Coop

Этот файл — главная инструкция для любого ИИ, который продолжает проект. `CLAUDE.md` просто ссылается сюда.
Если ты ИИ без доступа к репозиторию — попроси игрока прислать этот файл и `docs/ARCHITECTURE.md`.

Прочитай перед работой: `README.md` (что есть), `docs/ARCHITECTURE.md` (как устроено),
`docs/HISTORY.md` (почему так — найденные баги), `docs/libgtasa-2.10-arm64.md` (смещения игры).

## Игрок и его установка

* Общение — **на русском**, простыми словами, коротко. Игрок не программист: ему нужен готовый `.so`
  и понятная инструкция «что нажать». Тестирует сам на телефоне и присылает `sacoop.txt`, скриншоты, видео.
* Игра: GTA San Andreas Android **2.10, 64-bit**, **AML 1.4**, CLEO 64-bit (скрипты в `/storage/emulated/0/SA/cleo`).
  Моды игрока рядом с нашим: **SAUtils** (нужен нам), **Touch x4** (`libMultiTouch64.so`, 4 пальца — должно
  работать с нашими кнопками), **Helicover Brain** (свой мод игрока, на время коопа он его убирает — отключать
  из нашего мода не нужно).
* Друг играет из Бельгии, игрок — из Турции. Связь пока через **Tailscale**, позже — свой сервер с кодами комнат.
* APK с разрешением микрофона и созданием `SA/cleo` собирается отдельной сессией на компьютере игрока
  по заданию `docs/handoff/apk-microphone.md`.

## Правила

* Работать в ветке **`ccr-ffecc13b-oyswo0`** репозитория `stredge/linux`; `main` не трогать.
  PR не создавать без просьбы.
* Репозиторий **`STREDGE/helicover-brain`** — только читать/скачивать, **ничего туда не писать**
  (там работает другая нейросеть).
* Файлы игры (`libGTASA.so`, APK, OBB) в репозиторий не класть.
* Не воссоздавать чужие игры/ассеты — только код мода.

## Сборка, проверка, выпуск

```sh
# NDK r27c (в облачной сессии лежал в /opt/android-ndk-r27c; хост dl.google.com должен быть разрешён)
$NDK/ndk-build NDK_PROJECT_PATH=. APP_BUILD_SCRIPT=jni/Android.mk NDK_APPLICATION_MK=jni/Application.mk -j8

# Перед первой сборкой — встроенный Tailscale (Go скачается сам; third_party/tsbridge в git нет):
NDK=/opt/android-ndk-r27c bash tools/tsbridge/build.sh

# Превью меню/интерфейса на компьютере (картинки .ppm в текущей папке):
mkdir -p /tmp/preview && cd /tmp/preview && bash <repo>/tools/preview/build.sh
```

Выпуск новой версии:
1. Поднять версию в `MYMODCFG(...)` в `src/main.cpp`.
2. Собрать, `cp libs/arm64-v8a/libSACoop.so release/`.
3. Обновить `release/README.txt` (версия + строка «что нового»), при заметных изменениях — `docs/HISTORY.md`.
4. Коммит, `git push -u origin ccr-ffecc13b-oyswo0`, отправить игроку `release/libSACoop.so` файлом.
5. Изменился сетевой протокол → `kProtocolVersion` +1 и сказать игроку, что обновиться должны **оба**.

Сценарий игры (миссии, маркеры, катсцены): выводы — `docs/main-scm-notes.md`, разборщик — `tools/scm/`
(файлы `mainV1.scm`/`scriptv1.img` в репозитории нет — попросить у игрока).

Отлаживать по логу игрока: `sacoop.txt` (и `sacoop_prev.txt` после вылета; там строка `ВЫЛЕТ … pc/lr`
и «Мод в момент вылета»). Для вылетов в игре полезен `aml_crashlog`, который присылает игрок.

## Чему научил опыт (не наступать снова)

* Не перехватывать `AND_TouchEvent` и не менять начало `CTouchInterface::IsTouchDown` /
  `LIB_PointerGetCoordinates` — ломает кнопки других модов. Касания — опросом `Points` через GOT `0x851D38`.
* Второго CJ трогать только из игрового потока; при сохранении игры ничего не делать.
* После создания второго CJ — обязательно `SetCharCreatedBy(2)`.
* Не создавать второго CJ раньше чем через 3 с после появления своего и во время катсцен.
* В `CAdjustableHUD` реагировать только на 2 (сохранить) и 3 (отмена) при закрытии; 4 — не «по умолчанию».
* В шрифте Rubik нет «→», «✓», «−».
* Беззнаковые разности времени — только через проверку порядка (`Since`).

## Второй мод: SA Living (ИИ-педы) — папка `sa-living/` (0.1.0, код есть, в игре не проверен; 0.2.0 на паузе — см. `sa-living/STATUS.md`)

Отдельный мод в папке `sa-living/` (свой код, своя сборка, свой `libSALiving.so`). **С коопом не смешивать**:
не подключать `src/` коопа, нужное копировать; общие — только `third_party/`.
План — `sa-living/DESIGN.md`. Главное: **ключ API в мод не вшивать** — игрок вставляет свой ключ Anthropic
в разделе «ИИ» (в конфиге, в лог не пишется, маскируется). Модель — Claude Haiku 5.5 (`claude-haiku-5-5`),
effort `low`. Педы строят поведение из «кирпичиков»-инструментов, а не выбирают одно действие.
Речь → текст и голос педов — средствами Android. Без ключа работает «мозг реализма» без интернета.

SA Living: сборка и устройство — `sa-living/README.md`. Кооп определяется сам через интерфейс AML `SACoopNet`
(SA Coop ≥ 0.7.0, `src/net/sacoop_api.h` — копия в `sa-living/src/net/`). Ключ вводится в плитке «AI» настроек игры.
Пространство имён связи — `coopnet` (не `link`: конфликт с POSIX `link()`).
