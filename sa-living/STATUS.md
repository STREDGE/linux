### Что упрощено против ТЗ (сказано игроку)

* Память ИИ **внутри `.sacoop`** не сделана — самого формата `.sacoop` в SA Coop ещё нет (ТЗ 1.1 §15).
  Сейчас кооп-ячейка получает свою память по имени файла (`SACoop_N`).
* «Другу можно менять мир через Джарвиса» проверяется только на стороне друга (хост не перепроверяет).
* Справочник команд (Sanny Builder `sa_mobile.json`, лицензия не указана) в мод не вшит — качается на телефон
  кнопкой во вкладке «Джарвис». Без него работают все готовые команды, не работают только «свободные» просьбы.
* «Мастер первого запуска» — это экран из 5 шагов-состояний во вкладке «Главное», а не отдельные окна.

### Что проверится только на телефоне (первым делом смотреть в логе)

`dlopen` движков из личной папки игры; скорость xVibe на телефоне (если медленнее речи — будут паузы);

пункт Jarvis в меню CLEO; запросы к Claude (ключа в облачной сессии не было).

## 2. Почему так (решения и их причины)

* **Piper** отклонён игроком (мало голосов, не нравится). **Vosk TTS** — мало голосов (5).
* **Pocket из sherpa-onnx** даёт плохую речь: в sherpa токенизатор SentencePiece *unigram*, а у xVibe — *BPE*;
  плюс зашит порог конца речи −4 (xVibe обучен на −1) → обрывы. Поэтому **свой движок** на ONNX Runtime C API:
  точный BPE (совпадение с SentencePiece проверено), цикл генерации один в один как
  `KevinAHM/pocket-tts-onnx` (`pocket_tts_onnx.py`), temperature 0.5, lsd 1 шаг, звук порциями по 12 кадров.
  ORT берём из того же AAR sherpa-onnx (`libonnxruntime.so` 1.24.3), движок просит API 24 — значит ORT ≥ 1.24.
* Разборчивость (распознаванием GigaAM, 6 фраз × 3): sherpa 67% → свой движок 80–94% в зависимости от голоса;
  встроенный голос xVibe `male_deep` — 94%, последнее слово 18/18. Таблицы — `tools/xvibe/README.md`.
* Текст перед синтезом чистится (`xvibe::PrepareText`): неизвестный символ (например `+` перед согласной)
  ронял ORT на Reshape. Ударения `+гласная` помогают: без них тот же текст распознаётся заметно хуже.
* Образцы для голосов: чтение вслух (FLEURS) — плохо; лучше спокойная разговорная речь 15–20 с без пауз и крика.

## 3. Мнение игрока об озвучке

* Демо 8 голосов (FLEURS) — «неотчётливо, быстро, обрываются».
* `docs/samples/xvibe_ru_10_voices_v2.wav` — понравились 3 голоса на **0:23, 0:27, 0:33**:
  Vosk M01 ×1.1, Vosk M02, Vosk F01 ×0.88 (Apache-2.0, `docs/samples/vosk/`).
* Варианты v3 (`xvibe_ru_12_voices_v3.wav`) — «обрываются, акцент как у мигрантов».
* Эталон родного кода автора (`xvibe_author_reference.wav`) — «пойдёт на первое время».
* Сделан клон голоса самого игрока (по его записи): родной код автора — почти без ошибок, наш движок —
  первая фраза смазана, остальное разборчиво. **Запись голоса игрока и клоны в репозиторий не класть**
  (личное). Лучший образец — 15–20 с спокойной речи. Идея: игрок может добавлять свои голоса (свой, друга).

## 4. Голосовой пакет (решение игрока — «вариант 1»)

Модели xVibe (дообучение, лицензия неясна, ~143 МБ) **в публичный репозиторий не кладём**. Пакет-zip
отправляется игроку файлом в чат → он сохраняет в `Download` → мод импортирует сам.
sherpa-onnx AAR и GigaAM мод скачивает сам (GitHub / Hugging Face) через `Bridge.downloadPack`.

Состав пакета xVibe (после экспорта и `tools/xvibe/patch_for_sherpa.py`):
`mimi_encoder.onnx`, `text_conditioner.onnx` (fp32), `flow_lm_main_int8.onnx` (72.8 МБ),
`flow_lm_flow_int8.onnx` (9.5 МБ), `mimi_decoder_int8.onnx` (21.6 МБ), `bundle.json`, `vocab.json`,
`token_scores.json` + голоса: XVST-состояния (сжаты gzip, ~5 МБ каждое) или wav-образцы (голос готовится при первом использовании, кэш LRU `voiceCache`).

Как получить модели заново — `tools/xvibe/README.md` (экспорт `lomotron/pocket-tts-onnx-export` с `--config`,
в облаке Hugging Face качать с `HF_HUB_DISABLE_XET=1`).

## 6. Проверка на компьютере (как это делалось)

```sh
# из папки sa-living; ORT и sherpa для x86 — из pip-пакета sherpa-onnx (его папка lib), модели — в <base>/asr и <base>/tts
g++ -O2 -std=c++17 -Isrc -Itools/hosttest tools/hosttest/chain.cpp tools/hosttest/stub.cpp \
    src/speech/speech.cpp src/speech/xvibe.cpp src/util/json.cpp -ldl -lz -lpthread -o chain
./chain <base> <папка с libonnxruntime.so и libsherpa-onnx-c-api.so> <куда писать wav>

g++ -O1 -std=c++17 -Isrc -Itools/hosttest tools/hosttest/jarvis_test.cpp src/jarvis/brain.cpp src/util/json.cpp -o jarvis_test
./jarvis_test [sa_mobile.json]          # разбор фраз без ИИ + справочник

mkdir -p /tmp/p && cd /tmp/p && bash <repo>/sa-living/tools/preview/build.sh   # картинки меню (.ppm)
```

Голосовой пакет `SALiving-voices.zip` (в репозитории его нет): в корне `tts/` (8 файлов модели + `voices/voices.json`
и `*.xvst`, сжатые gzip — делает `tools/hosttest/make_voices.cpp`) и `lib/` (arm64 `libonnxruntime.so`,
`libsherpa-onnx-c-api.so` из AAR sherpa-onnx 1.12.40). Мод ищет в «Загрузках» zip, в имени которого есть
«saliving» и «voice».

## Согласовано с игроком для коопа (2026-11-25)

Полные правила — `docs/TZ-1.1.md` §7а (в корне репозитория). Коротко: **платит хост всегда** — в коопе мозг и ключ только у хоста (ключ друга в коопе не используется, только в его соло); ключ не вшивается
и не передаётся; друг с модом без ключа получает всё через мозг; далеко друг от друга — восприятие от SA Living
друга → решение мозга → выполняет SA Living друга на своих педах; память у мозга; «мозг реализма» на каждом
телефоне свой. Друг **без** SA Living: субтитры и голос педов через SA Coop, говорит через микрофон коопа →
распознавание на телефоне мозга (нужен GigaAM из 0.2), педы с поведением SA Living не уходят к нему.
